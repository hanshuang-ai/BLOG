`git版本控制就是通过不同的节点保存代码的各个阶段，同时在每次提交代码的时候需要填写提交信息`

# 克隆
`git clone 仓库地址`
*注意：如果配置了多个git账户，则需要区分仓库地址使用的事git还是https，要依据自己配置的config文件进行确定*

# 添加（暂存）
`git add .`
*注意：后面的 . 不能省略，. 代表的是将所有的更改都暂存起来*

# 填写提交信息
`git commit -m '提交信息'`
*注意：提交信息一定要见名知意，这样在后续回退的时候能更快的知道需要回退到哪个版本，做到真正的版本管理*

**每次在提交前填写 commit -m 的命令时，推荐使用vscode插件 `git-commit-plugin`，这样可以使我们的提交信息更加丰富，方便管理**

# 提交到仓库
## 线上与线下分支不存在冲突的时候
当明确知道线上分支与当前线下分支版本一致，不存在冲突的时候。可以直接使用`git push`
## 线上与线下存在冲突的时候
因为一个项目需要多人在同一个仓库后者分支上开发，有时候就会出现别人的代码已经上传到git，但是自己本地未更新，这样在本地开发完成后，需要上传的时候就会提示需要先拉取最新的线上版本，与本地处理冲突后，然后再提交到仓库。
`冲突的产生是不同的开发者开发了同一个文件所导致，如果不同的开发者开发的不是同一个文件，则可以直接上传成功。`
**这很好理解：不同的开发者开发不同的文件，git上传的时候直接直接替换即可，但是如果开发的是同一个文件，那么git就会产生以谁的文件为最终结果的疑问，这就是冲突的由来，我们只有解决好冲突后，才能在解决的基础上连同自己添加的文件一并上传**
`所以一般的开发习惯就是在 git push之前，先git pull拉取下`

*注意：提交的时候git会自动根据本地当时所处的分支提交到线上对应的分支，这一点至关重要，假如线上、线下同时具有dev和version分支，且本地处于version分支，那么上传时会自动传输到version分支，造成混乱。所以需要确定当前所处分支，需要上传到线上的分支，当分支不对的时候就需要切换*

# 切换分支
## 查看分支
分支切换的前提是知道有哪些分支，所以需要先查看下
### 查看本地分支（线下）
`git branch`
*命令输入后，如果本地存在分支，则会全部列出*
### 查看所有分支（线上和线下）
`git branch -a`
* -a 就是 -all的意思，即查看所有分支（线上和线下）*
## 切换分支
查看分支完毕，就需要切换分支
### 切换到本地已经存在的分支
`git checkout 分支名称`
### 要切换的分支本地并不存在，想创建一个分支并切换过去
`git checkout -b 分支名称`
*注意：当使用`git checkout -b 分支名称`创建一个新分支的时候，如果线上也没有这个分支，则`git push`的时候会自动在线上创建该分支，这也是刚在上面所说的`git push`的时候需要注意本地当前所处分支的原因*

# 下拉
## 下拉之前先检查线上分支与本地分支是否一致
`git fetch`
## 下拉之前不检查，直接下拉
`git pull`
*注意：git pull是在不检查的情况下直接拉取，有可能下拉下来后与本地分支存在冲突，需要手动解决*
## 本地已经做的更改不想保存，直接下拉线上版本进行覆盖
